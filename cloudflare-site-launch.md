## Phase 1 — Cloudflare Worker scaffold

### 1.1 Create `wrangler.toml`

Generate from config:

```toml
name = "{{site.worker_name}}"
main = "src/worker.js"
compatibility_date = "2024-05-15"

[assets]
directory = "./"
binding = "ASSETS"
not_found_handling = "404-page"
run_worker_first = true

[[routes]]
pattern = "{{site.domain}}"
custom_domain = true

[[routes]]
pattern = "www.{{site.domain}}"
custom_domain = true

[[secrets_store_secrets]]
binding = "SENDGRID_API_KEY"
store_id = "{{site.sendgrid.secrets_store_id}}"
secret_name = "SENDGRID_API_KEY"
```

`SENDGRID_API_KEY` is the **only** Secrets Store binding. `RECAPTCHA_SECRET` is a Worker Secret and
is never declared in `wrangler.toml` — see below.

**Critical:** Route patterns are bare hostnames. No `/*` — `custom_domain = true` rejects wildcards.

**Critical — `run_worker_first = true`:** without it, Cloudflare serves static assets directly at
the edge and the worker never runs for them, so the security headers (HSTS/CSP/COOP) and the
canonical `Link` header are absent on every real page. With it, every request enters the worker,
which then calls `env.ASSETS.fetch` and wraps the response via `withSecurityHeaders()`. Trade-off:
the worker is invoked on every request (negligible cost for a brochure site; this is the intended
behaviour for a hardened deploy).

**Critical — `RECAPTCHA_SECRET` is a Worker Secret, not a Secrets Store secret.** It is added
directly on the worker: **Workers & Pages → `{{site.worker_name}}` → Settings → Variables and Secrets
→ Add → type: Secret → name `RECAPTCHA_SECRET`** (or `npx wrangler secret put RECAPTCHA_SECRET`).
Encrypted **Secrets** persist across deploys — only plaintext **Variables** (the `[vars]` table) are
reconciled against the config and wiped. Because a Worker Secret is set out-of-band, it appears
nowhere in `wrangler.toml`; there is no store ID for it, and `site.recaptcha_secret_store_id` is not
a config key. Secrets Store is used for `SENDGRID_API_KEY` only, because that key is shared across
every Avily site.

### 1.2 Create `src/worker.js`

**Preferred:** run `node scripts/build-worker.js` — it renders `src/worker.js` from
`templates/worker.template.js`, substituting domain, emails, business name and a `LAST_MODIFIED`
**derived from `build_date`** (no hand-computing the weekday). Re-run it whenever those change.

The verbatim worker below is the source of truth for `templates/worker.template.js` (tokens replace
`{{site.domain}}`, `{{site.contact.email}}`, `{{site.business_name}}`, `{{site.sendgrid.from_email}}`, `{{site.build_date}}`):

```js
// Cloudflare Worker: static site + contact form handler (hardened)
//
// Bindings:
//   SENDGRID_API_KEY   - Secrets Store binding (shared across Avily sites)
//   RECAPTCHA_SECRET   - Worker Secret (v3 secret key), set on the worker under
//                        Settings > Variables and Secrets — NOT in Secrets Store
//   ASSETS             - Static assets binding (auto-created by [assets])

const FORM_ENDPOINT = "/PHPFORMS/contact-form";
const CANONICAL_HOST = "{{site.domain}}";   // canonical apex (or www, per site.canonical_host)
const NON_CANONICAL_HOST = "www.{{site.domain}}"; // gets 301-redirected to CANONICAL_HOST
const LAST_MODIFIED = "Mon, 12 May 2026 00:00:00 GMT"; // bump per deploy

const ALLOWED_ORIGINS = new Set([
  "https://{{site.domain}}",
  "https://www.{{site.domain}}",
  "http://localhost:8787",
  "http://127.0.0.1:8787",
]);

function corsFor(request) {
  const origin = request.headers.get("Origin") || "";
  const allow = ALLOWED_ORIGINS.has(origin) ? origin : "https://{{site.domain}}";
  return {
    "Access-Control-Allow-Origin": allow,
    "Access-Control-Allow-Methods": "POST, OPTIONS",
    "Access-Control-Allow-Headers": "Content-Type",
    "Vary": "Origin",
  };
}

function escapeHtml(value) {
  return String(value ?? "")
    .replace(/&/g, "&amp;")
    .replace(/</g, "&lt;")
    .replace(/>/g, "&gt;")
    .replace(/"/g, "&quot;")
    .replace(/'/g, "&#39;");
}

const STATIC_ASSET_RE = /\.(css|js|mjs|png|jpe?g|gif|webp|avif|svg|ico|woff2?|ttf|otf|eot|webmanifest|xml|txt|map|mp4|webm)$/i;

function cacheControlFor(pathname) {
  if (STATIC_ASSET_RE.test(pathname)) return "public, max-age=86400, s-maxage=2592000";
  return "public, max-age=300, s-maxage=3600";
}

const SECURITY_HEADERS = {
  "Strict-Transport-Security": "max-age=31536000; includeSubDomains; preload",
  "X-Content-Type-Options": "nosniff",
  "X-Frame-Options": "SAMEORIGIN",
  "Cross-Origin-Opener-Policy": "same-origin-allow-popups",
  "Referrer-Policy": "strict-origin-when-cross-origin",
  "Permissions-Policy": "camera=(), microphone=(), geolocation=(), interest-cohort=()",
  "Content-Security-Policy": [
    "default-src 'self'",
    "script-src 'self' https://www.google.com/recaptcha/ https://www.gstatic.com/recaptcha/ https://www.googletagmanager.com https://static.cloudflareinsights.com 'unsafe-inline'",
    "frame-src https://www.google.com https://maps.google.com https://www.googletagmanager.com",
    "style-src 'self' 'unsafe-inline' https://fonts.googleapis.com",
    "font-src 'self' https://fonts.gstatic.com data:",
    "img-src 'self' data: https:",
    "media-src 'self'",
    "connect-src 'self' https://www.google.com/recaptcha/ https://www.googletagmanager.com https://www.google-analytics.com https://analytics.google.com https://cloudflareinsights.com https://static.cloudflareinsights.com",
    "form-action 'self'",
    "base-uri 'self'",
    "object-src 'none'",
  ].join("; "),
};

function isHtmlPath(pathname) {
  return pathname === "/" || /\.html?$/i.test(pathname) || !/\.[a-z0-9]+$/i.test(pathname);
}

function canonicalUrlFor(pathname) {
  let p = pathname === "/index.html" ? "/" : pathname;
  return `https://${CANONICAL_HOST}${p}`;
}

function withSecurityHeaders(response, pathname) {
  const headers = new Headers(response.headers);
  for (const [k, v] of Object.entries(SECURITY_HEADERS)) headers.set(k, v);
  if (pathname && !headers.has("Cache-Control")) {
    headers.set("Cache-Control", cacheControlFor(pathname));
  }
  if (pathname && isHtmlPath(pathname)) {
    if (!headers.has("Last-Modified")) headers.set("Last-Modified", LAST_MODIFIED);
    if (!headers.has("Link")) {
      headers.set("Link", `<${canonicalUrlFor(pathname)}>; rel="canonical"`);
    }
  }
  return new Response(response.body, {
    status: response.status,
    statusText: response.statusText,
    headers,
  });
}

export default {
  async fetch(request, env, ctx) {
    const url = new URL(request.url);

    // www → apex 301 (eliminate duplicate content)
    if (url.hostname === NON_CANONICAL_HOST) {
      return new Response(null, {
        status: 301,
        headers: {
          Location: `https://${CANONICAL_HOST}${url.pathname}${url.search}`,
          "Cache-Control": "public, max-age=3600",
        },
      });
    }

    if (url.pathname === FORM_ENDPOINT) {
      const cors = { ...corsFor(request), "Cache-Control": "no-store" };
      if (request.method === "OPTIONS") {
        return withSecurityHeaders(new Response(null, { status: 204, headers: cors }));
      }
      if (request.method === "POST") {
        return withSecurityHeaders(await handleForm(request, env, cors));
      }
      return withSecurityHeaders(
        new Response("Method Not Allowed", { status: 405, headers: cors })
      );
    }

    const assetResponse = await env.ASSETS.fetch(request);
    return withSecurityHeaders(assetResponse, url.pathname);
  },
};

async function handleForm(request, env, cors) {
  const requestId = crypto.randomUUID();
  try {
    const contentType = request.headers.get("content-type") || "";
    let data;
    if (contentType.includes("application/json")) {
      data = await request.json();
    } else {
      const formData = await request.formData();
      data = Object.fromEntries(formData);
    }

    const {
      emailaddress, sendermessage, telephone, username, token,
      first_name, last_name, service, website,
    } = data;

    // Honeypot — fake success so bots never learn they were blocked.
    if (website && String(website).trim().length > 0) {
      console.log("form_submission", { requestId, status: "rejected_honeypot" });
      return Response.json({ success: true }, { status: 200, headers: cors });
    }

    if (!token) {
      console.log("form_submission", { requestId, status: "rejected_no_token" });
      return Response.json(
        { success: false, error: "No captcha token" },
        { status: 400, headers: cors }
      );
    }

    const recaptchaResponse = await fetch(
      "https://www.google.com/recaptcha/api/siteverify",
      {
        method: "POST",
        headers: { "Content-Type": "application/x-www-form-urlencoded" },
        body: new URLSearchParams({
          secret: env.RECAPTCHA_SECRET,
          response: token,
          remoteip: request.headers.get("CF-Connecting-IP") || "",
        }),
      }
    );

    const recaptchaResult = await recaptchaResponse.json();
    if (!recaptchaResult.success || (recaptchaResult.score ?? 0) < 0.5) {
      console.log("form_submission", {
        requestId,
        status: "rejected_recaptcha",
        score: recaptchaResult.score ?? null,
      });
      return Response.json(
        { success: false, error: "Captcha verification failed" },
        { status: 403, headers: cors }
      );
    }

    const sendgridKey = await env.SENDGRID_API_KEY.get();

    const serviceRow = service && String(service).trim()
      ? `<b>Service:</b> ${escapeHtml(service)}<br/>`
      : "";

    const emailBody = `
    <html>
      <p>
        <b>First Name:</b> ${escapeHtml(first_name)}<br/>
        <b>Last Name:</b> ${escapeHtml(last_name)}<br/>
        <b>Telephone:</b> ${escapeHtml(telephone)}<br/>
        <b>Email:</b> ${escapeHtml(emailaddress)}<br/>
        ${serviceRow}
        <b>Message:</b> ${escapeHtml(sendermessage)}
      </p>
    </html>`;

    const emailResponse = await fetch("https://api.sendgrid.com/v3/mail/send", {
      method: "POST",
      headers: {
        Authorization: `Bearer ${sendgridKey}`,
        "Content-Type": "application/json",
      },
      body: JSON.stringify({
        personalizations: [
          { to: [{ email: "{{site.contact.email}}", name: "{{site.business_name}}" }], subject: "Website Contact Request" },
        ],
        from: { email: "{{site.sendgrid.from_email}}", name: username },
        reply_to: { email: emailaddress, name: username },
        subject: "Website Contact Request",
        content: [{ type: "text/html", value: emailBody }],
      }),
    });

    if (!emailResponse.ok) {
      const errText = await emailResponse.text();
      console.error("form_handler_failed", {
        requestId,
        stage: "sendgrid",
        status: emailResponse.status,
        details: errText,
      });
      return Response.json(
        { success: false, error: "Email send failed", status: emailResponse.status, details: errText },
        { status: 500, headers: cors }
      );
    }

    console.log("form_submission", { requestId, status: "accepted" });
    return Response.json({ success: true }, { headers: cors });
  } catch (err) {
    console.error("form_handler_failed", {
      requestId,
      stage: "handler",
      err: err && err.message,
      stack: err && err.stack,
    });
    return Response.json(
      { success: false, error: "Internal error" },
      { status: 500, headers: cors }
    );
  }
}
```

a Secrets Store secret, and not in `wrangler.toml`. Ask the user to add the **v3 secret key** (server

- Dashboard → **Workers & Pages → `{{site.worker_name}}` → Settings → Variables and Secrets → Add** →
  type **Secret** → name `RECAPTCHA_SECRET` (i.e. `site.recaptcha_secret_name`) → paste the v3 secret
  key as the value.
- Or CLI: `npx wrangler secret put RECAPTCHA_SECRET`.

The worker must already exist for the dashboard route to be available, so on a brand-new site the
order is: first `npx wrangler deploy` → add the secret → redeploy or just re-test the form.

Also confirm the SendGrid Secrets Store binding exists on this Cloudflare account (store

## Phase 2 — Contact form

### 2.1 Create `js/ContactUs.js`

**Preferred:** run `node scripts/build-contact-js.js` — it renders `js/ContactUs.js` from
`templates/ContactUs.template.js`, substituting `site.recaptcha_site_key` (it fails loudly if the key
is still the placeholder). Phase 2.2's `standardize-forms.js` also calls this automatically, so the
`<script src="js/ContactUs.js">` tag it injects always resolves to a real, rendered file. Re-run
after changing the site key. The rendered source, for reference (`{{site.recaptcha_site_key}}` is the
substituted value):

```js
const RECAPTCHA_SITEKEY = "{{site.recaptcha_site_key}}";

async function onSubmit(event) {
    if (event) event.preventDefault();
    const form = event?.target?.closest("form");
    if (!form) return;

    const first_name   = form.querySelector('input[name="first_name"]')?.value.trim() || "";
    const last_name    = form.querySelector('input[name="last_name"]')?.value.trim() || "";
    const emailaddress = form.querySelector('input[name="emailaddress"]')?.value.trim() || "";
    const telephone    = form.querySelector('input[name="telephone"]')?.value.trim() || "";
    const sendermessage = form.querySelector('textarea[name="sendermessage"]')?.value.trim() || "";
    const service      = form.querySelector('select[name="service"]')?.value || "";
    const website      = form.querySelector('input[name="website"]')?.value || ""; // honeypot
    const username     = `${first_name} ${last_name}`.trim();

    if (!username || !emailaddress || !telephone || !sendermessage) {
        alert("Please complete the form");
        return;
    }

    if (typeof grecaptcha === "undefined") {
        alert("Captcha has not loaded. Please refresh and try again.");
        return;
    }

    let token = "";
    try {
        token = await new Promise((resolve, reject) => {
            grecaptcha.ready(() => {
                grecaptcha.execute(RECAPTCHA_SITEKEY, { action: "submit" }).then(resolve, reject);
            });
        });
    } catch (err) {
        alert("Captcha verification failed. Please try again.");
        return;
    }

    const payload = {
        username, emailaddress, telephone, sendermessage,
        first_name, last_name, service, website, token,
    };

    try {
        const response = await fetch("/PHPFORMS/contact-form", {
            method: "POST",
            body: JSON.stringify(payload),
            headers: { "Content-Type": "application/json" },
        });
        if (!response.ok) {
            let message = `Submission failed (${response.status})`;
            try {
                const data = await response.json();
                if (data && data.error) message = data.error;
            } catch (_) {}
            alert(message);
            return;
        }
        window.location.href = "/thank-you.html";
    } catch (error) {
        alert(error.message);
    }
}
```

### 2.2 Standardize every form

**Preferred:** run `node scripts/standardize-forms.js` — it applies all of the rules below across
every page with a `<form>` (renames fields, adds the honeypot, converts the submit button, injects the
reCAPTCHA + `ContactUs.js` script tags) and is idempotent. Verify the result, then hand-tweak only if
needed. The spec it implements, for reference:

For every HTML page that contains a `<form>`, ensure:

- `<form onsubmit="event.preventDefault(); return false;">` (drop any `action=` and `method=`).
- Input `name` attributes:
  - `first_name`, `last_name` (rename `username` → `first_name` if present)
  - `emailaddress` (NOT `email`)
  - `telephone` (NOT `phone`)
  - `sendermessage` (NOT `message`) — must be `<textarea>`
  - `service` (optional `<select>`)
  - `website` — **honeypot**, invisible input:
    ```html
    <input type="text" name="website" tabindex="-1" autocomplete="off" aria-hidden="true" style="position:absolute;left:-9999px;width:1px;height:1px;opacity:0">
    ```
- Submit button: `<button class="g-btn ..." onclick="onSubmit(event)" type="button">Submit</button>` — `type="button"` is critical.
- In `<head>`, **once per page**:
  ```html
  <script async defer src="https://www.google.com/recaptcha/api.js?render={{site.recaptcha_site_key}}"></script>
  <script src="js/ContactUs.js" defer></script>
  ```

(See `scripts/optimize-images.js` reference — same as v1 but reads `OG_SOURCE_CANDIDATES` from config. Default falls back to: hero image of the page with `schema_role: home`, then the `about` page's hero, then any image in `images/` matching `*hero*` or `*about*`.)

### 6.3 **(STOP — manual step)** Run the image pipeline

`package.json` and `js-yaml` were already installed in Phase 0; this step only adds the heavy native
`sharp` dependency and generates the images. Ask the user to run:

```bash
npm install         # pulls sharp (prebuilt binaries on most platforms)
npm run optimize-images
```

This generates `images/optimized/<webp + responsive widths + jpg fallback>` and `images/optimized/manifest.json` plus `images/og-default.jpg`. Tune `site.images.size_threshold_kb` to control which images get the responsive treatment (default 200 KB; smaller images are left as-is — **lower to ~15 KB** to also optimize 20–50 KB content images, while still skipping ~1 KB icons that gain nothing). Set `site.images.skip` (array of repo-relative dirs, e.g. `images/home/team`) to exclude unreferenced assets so they don't produce orphan optimized output.

### 6.4 Automated `<img>` → `<picture>`

```bash
node scripts/inject-pictures.js
```

Reads `manifest.json` + walks all HTML files. For every `<img src="images/x.jpg">` where `x.jpg` is in the manifest, rewrites to:

```html
<picture>
  <source type="image/webp" srcset="
    images/optimized/x-480.webp 480w,
    images/optimized/x-800.webp 800w,
    images/optimized/x-1200.webp 1200w,
    images/optimized/x-1920.webp 1920w" sizes="(max-width: 800px) 100vw, 50vw">
  <img src="images/optimized/x.jpg" alt="<preserved>" width="W" height="H" loading="lazy">
</picture>
```

Width and height come from manifest (prevents CLS). The first `<img>` inside each page's `<main>` gets `fetchpriority="high"` instead of `loading="lazy"` (LCP candidate).

> **v3.1:** the WebP `<source>` srcset is built from the manifest's stored paths, so images in
> subdirectories (`images/home/x.jpg`) get correct `images/optimized/home/x-480.webp` URLs (older
> builds reconstructed from the basename and produced a broken srcset for nested images).

### 6.5 CSS background images (manual — `image-set()`)

`inject-pictures.js` only rewrites `<img>` tags. Hero/section images set via CSS
`background-image: url(...)` (often the **largest** files on the page) are **not** touched. After
`optimize-images.js` has produced their WebP/JPEG outputs, wire each one up by hand with a progressive
`image-set()` — a plain `url()` fallback line first (for browsers without `image-set`), pointing at
the optimized JPEG, then the `image-set()` with WebP:

```css
.hero {
  background-image: url('images/optimized/home/slide.jpg'); /* fallback */
  background-image: image-set(
    url('images/optimized/home/slide.webp') type('image/webp'),
    url('images/optimized/home/slide.jpg')  type('image/jpeg'));
}
```

Find these with a grep for `background-image:\s*url\(` across HTML (inline `<style>`) and CSS files.
Even the fallback line is a win — it points at the optimized JPEG, not the original.
